# 名片 · 本地商圈信息板

> 让一条街上的店，互相看得见；让钱，留在本地打转。

一个**零抽成、零服务器、零平台**的本地商圈工具。跑在商家自己的旧手机或电脑上，
只做一件事：**信息暴露**。

## 三条红线（代码里也写着）

| 不做 | 因为 |
|---|---|
| **不标价格** | 没有价格数据可卖，就没有比价、竞价排名、价格战 |
| **不做评价** | 没有评分体系，就没有刷单、没有差评师勒索、没有人能限你的流 |
| **不承载交易** | 钱不经过工具，就没有佣金、没有资金沉淀、不构成"平台经营者" |

这三条不是道德承诺，是**结构性约束**：工具里根本没有那些字段，
所以"屠龙少年变恶龙"需要的那个权力位，压根不存在。

## 快速开始

```bash
cd doorplate
python server.py            # 默认 8000 端口，纯标准库，无需安装任何依赖
```

启动后终端会打印四个入口地址（把 `192.168.x.x` 换成终端显示的实际地址）：

| 入口 | 地址 | 谁用 |
|---|---|---|
| 逛街 | `http://<IP>:8000/index.html` | 顾客：这条街上有什么 |
| 我的店 | `http://<IP>:8000/shop.html` | 商家：上货、改信息、开关门 |
| 电子名片 | `http://<IP>:8000/board.html?id=<店铺id>` | 挂在店门口的那块屏幕 |
| 运力 | `http://<IP>:8000/rider.html` | 骑手：发运力名片 |

手机与电脑连**同一个 WiFi** 即可访问。

## 核心设计：开关门 = 在线/离线

商家点一下「开门」，这条街就看得见他；点「关门」，立刻消失。
**物理状态就是网络状态**，没有心跳包、没有保活、没有"幽灵店铺"。

## 在旧安卓手机上跑（零成本节点）

```bash
# 1. 从 F-Droid 安装 Termux（Play 商店版已弃更）
pkg update && pkg upgrade -y
pkg install python -y

# 2. 把 doorplate 目录拷进手机，然后
cd ~/doorplate
termux-wake-lock
python server.py 8000
```

三个必须处理的坑：

| 坑 | 处理 |
|---|---|
| Android 12+ 会静默杀掉后台进程 | 关掉 Termux 的电池优化；必要时用 ADB 关闭 phantom process killer |
| 电池长期满电会鼓包 | 限充 40–80%（root 用 ACC；非 root 用定时插座） |
| 发热降频 | 5–10W 慢充、平放、别盖东西 |

## 底图：离线优先

程序优先读 `web/tiles/{z}/{x}/{y}.png`，读不到才连在线 OSM，都不通就降级为
"相对位置点阵"并提示。**中国网络下 OSM 官方瓦片经常连不上（实测 8 秒超时），
所以离线瓦片是必需品**，做法见 [`web/tiles/README.md`](web/tiles/README.md)。

## 同步：三条通道

数据就是 `data/` 目录下的 JSON 文件，**拷走就是备份**。

| 通道 | 状态 | 说明 |
|---|---|---|
| 局域网 localStorage | ✅ 已实现 | 服务端提供 `manifest` / `pull` / `push` / `export` 四个接口 |
| 同 WiFi 自动发现 | ⏳ 待做 | 计划用 mDNS 自动发现同网节点并增量同步 |
| 骑手携带（擦肩同步） | ⏳ 待做 | 骑手手机作为数据包，路过就交换增量，零公网依赖 |

现有的同步接口按 `updated` 时间戳**后写覆盖**，旧记录推不进来（已测）。

手动同步示例：

```bash
curl -s http://127.0.0.1:8000/api/sync/manifest
curl -s -X POST http://127.0.0.1:8000/api/sync/pull -H "Content-Type: application/json" -d '{"have":{}}'
curl -s http://127.0.0.1:8000/api/sync/export      # 整包导出，谁都能拷走
```

## 已知限制（原型阶段）

1. **二维码依赖 CDN**：离线时退化为大字网址，后续改为服务端本地生成
2. **无身份认证**：只有简单的 token 防误改，不适合公网暴露
3. **同步靠手动触发**：自动发现与骑手携带通道尚未实现
4. **地图点位需手动选点**：尚未接入 GPS 自动定位
5. **合规注意**：本工具仅供熟人之间非营利的顺路捎带；以收费运输为常业的，
   需依《道路运输条例》取得许可。工具不提供公网服务，因此不涉及 ICP 备案；
   一旦对外网开放，需自行评估备案与合规责任。

│   ├── core.js          # 事件流+认领+担保引擎（浏览器与 Node 共用）
│   ├── selftest.cjs     # JS 引擎自检 + 跨语言互验（27 项）
│   └── interop.py       # Python ↔ JS 签名互验脚本
├── p2p/                 # 事件流参考实现（Python）
│   ├── identity.py      # 签名与设备指纹
│   ├── store.py         # 事件、归约、担保链
│   ├── selftest.py      # 29 项自检
│   └── demo.py          # 五台手机碰面演示
├── cloud/               # 微信云开发上传链路
└── web/
    ├── index.html       # 顾客：地图 + 列表

## 本地优先应用（app/）

`python server.py` 之后打开 `http://<IP>:8000/app/index.html`，手机浏览器直接用。

三个页面：

| 页面 | 做什么 |
|---|---|
| **逛逛** | 搜索（店名/货品/街道）· 全部/收藏/商店/运力 筛选 · **列表 / 地图双模式** |
| **发布** | 贴一张商店名片或运力名片，两者都能在地图上选点 |
| **我的** | 我发布的（歇业/删除/分享） · 收藏清单 · 设备与同步 |

**没有担保流程**——谁标注的就算谁的，界面上一眼能看出「我发布的」还是「邻里标注」。

其他特性：

- **收藏**：点卡片右上角星标，按「收藏」筛选只看常去的店（存在本机）
- **歇业开关**：我的发布里一键歇业/开业，营业状态不会自己过期
- **分享二维码**：把某张名片生成二维码，邻居点右上角**扫一扫**，对准就自动收进手机
  - **实时取景**：摄像头画面逐帧丢给 jsQR，对准就识别，不用先拍照；拿不到摄像头才退回「拍一张再认」
  - 二维码里**只有店铺数据，不含任何服务器地址**——换台电脑、换个网络，码照样有效
  - 二维码在客户端本地生成（`app/qrcode.js`），解码在本地（`app/jsQR.js`），全程不走网络
  - 收下来的名片带「邻居捎来」标记：**进不了「我的发布」，也没有歇业/删除按钮**。
    只有原发布者本人才动得了它；捎来的这份想清掉，用详情页底部「从我这台手机上移除」
- **真地图 + 离线**：瓦片由服务端代理（`/tiles/{z}/{x}/{y}.png`）并落盘到 `data/tiles/`，
  手机端同源加载，无跨域；服务端攒下多少，断网就能看多少
- **自动同步**：服务端同时是局域网**存转发节点**（`/api/p2p/push`、`/api/p2p/pull`），
  两台手机各推各拉，不用复制粘贴

> 首次打开某片区域要等地图加载（每张瓦片约 1 秒），加载过的会落盘，之后秒开。
> URL 支持 `?page=xxx&mode=map&pub=rider&q=关键词&add=<分享码>` 直接打开某个状态。
