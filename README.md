# 名片 · 一个装在自己手机里的名片钱包

> 名片只递给你认识的人，不给平台。

[项目主页](https://wbapp-9a7xpyiixluucbdpwlcz6i.app.workbuddy.host/?sharecode=NNFXYE3XID) · [直接下载 APK](https://wbapp-9a7xpyiixluucbdpwlcz6i.app.workbuddy.host/assets/cardlet.apk) · [MIT 许可](LICENSE) · 纯标准库零依赖 · 不联网也能跑

一个**零抽成、零服务器、零平台**的数字名片钱包。每台手机就是一个独立钱包，
名片靠面对面扫码交换；开启自动同步后，同一个 WiFi 下的两台手机只会
**比对双方都已持有的名片版本**，把过期的补齐。

它不是发布平台：**你没扫过的名片，永远不会出现在你手机里。**

## 三条红线（代码里也写着）

| 不做 | 因为 |
|---|---|
| **不标价格** | 没有价格数据可卖，就没有比价、竞价排名、价格战 |
| **不做评价** | 没有评分体系，就没有刷单、没有差评师勒索、没有人能限你的流 |
| **不承载交易** | 钱不经过工具，就没有佣金、没有资金沉淀、不构成"平台经营者" |

名片的数据结构里没有价格、评分、交易这些字段，所以也没有可以关掉的开关。

## 快速开始

```bash
cd cardlet
python server.py            # 默认 8000 端口，纯标准库，无需安装任何依赖
```

启动后终端会打印入口地址（把 `192.168.x.x` 换成终端显示的实际地址）。

**当前形态的入口是 `app/`**，手机浏览器直接打开：

```
http://<IP>:8000/app/index.html
```

手机与电脑连**同一个 WiFi** 即可访问。想先看效果，在地址后面加 `?demo=1`，会塞四张示例名片。

URL 还支持直接打开某个状态：`?page=mine|settings|edit|card`、`?mode=map`、`?w=390`（限宽自测）。

> 终端打印的「顾客 / 店主 / 电子名片 / 骑手」四个页面来自 `web/`，
> 是「商圈信息板」时代留下的早期版本，保留仅作参考，不是当前形态。

## 打包成 APK

```bash
bash android/build.sh          # 产出 cardlet.apk
```

需要 Android SDK 的 `aapt2` / `d8` / `apksigner`，**不需要 Gradle**。
`debug.keystore` 刻意不入库，第一次构建时脚本会自动生成一个。

## 核心设计：名片有主人

一张名片只有一个主人，也只有主人能改。钱包里存的是**别人名片的副本**。

- 主人改完内容，版本号 +1，重新生成二维码
- 你扫到同一张名片时，只比版本号：比你的新就替换，跟你的平或旧就提示「已是最新版」
- 所以「同步」不是交换新名片，而是**刷新已有名片的版本** —— 这一条决定了整个架构

**只同步双方都存在的名片**：连了谁的 WiFi，也不会因此多出陌生人来。


三个必须处理的坑：

| 坑 | 处理 |
|---|---|
| Android 12+ 会静默杀掉后台进程 | 关掉 Termux 的电池优化；必要时用 ADB 关闭 phantom process killer |
| 电池长期满电会鼓包 | 限充 40–80%（root 用 ACC；非 root 用定时插座） |
| 发热降频 | 5–10W 慢充、平放、别盖东西 |

## 底图：离线优先

瓦片由服务端代理（`/tiles/{z}/{x}/{y}.png`）并落盘到 `data/tiles/`，
手机端同源加载，没有跨域问题；服务端攒下多少，断网就能看多少。
都读不到时降级为「相对位置点阵」并提示。

**中国网络下 OSM 官方瓦片经常连不上（实测 8 秒超时），所以离线瓦片是必需品。**
自己切片的做法见 [`web/tiles/README.md`](web/tiles/README.md)。

> OSM 官方瓦片受[使用条款](https://operations.osmfoundation.org/policies/tiles/)限制，
> 不可批量下载或再分发，所以**本仓库不含任何瓦片文件**，`data/tiles/` 由运行时自己攒。

## 同步：三条通道

| 通道 | 状态 | 说明 |
|---|---|---|
| 二维码 | ✅ 主力 | 一方屏幕一方摄像头；码内只有名片数据，不含任何服务器地址 |
| 同 WiFi 自动发现 | ✅ 已实现 | APK 内 `LocalNode.java`：UDP 47474 广播发现 + `/24` 单播兜底，HTTP 47475 交换；网页版走 `POST /api/p2p/exchange` |
| 骑手携带（擦肩同步） | ⏳ 未做 | 骑手手机作为数据包，路过就交换增量，零公网依赖 |

> 手机端数据存在 `localStorage`（事件日志 + 私有的 `dp.imported` 标记）；
> `data/` 下的 JSON 是网页版旧接口读写的，拷走就是备份。

现有的同步接口按 `updated` 时间戳**后写覆盖**，旧记录推不进来（已测）。

手动同步示例：

```bash
curl -s http://127.0.0.1:8000/api/sync/manifest
curl -s -X POST http://127.0.0.1:8000/api/sync/pull -H "Content-Type: application/json" -d '{"have":{}}'
curl -s http://127.0.0.1:8000/api/sync/export      # 整包导出，谁都能拷走
```

## 已知限制（原型阶段）

1. **发现受路由器限制**：开了 AP 隔离（客户端隔离）的路由器上，两台手机互相看不见，
   自动同步不可用。这是网络策略，不是代码能绕过的
2. **签名是演示级**：纯标准库没有 Ed25519，这里用教科书式 RSA-1024；
   正式版应换 Ed25519（`cryptography` 库），体积小、速度快、无填充陷阱
3. **地图点位需手动选点**：尚未接入 GPS 自动定位
4. **字体依赖系统**：标题用的宋体在部分 ROM 上会退化成黑体
5. **合规注意**：本工具仅供熟人之间非营利的顺路捎带；以收费运输为常业的，
   需依《道路运输条例》取得许可。工具不提供公网服务，因此不涉及 ICP 备案；
   一旦对外网开放，需自行评估备案与合规责任。

## 本地优先应用（app/）

`python server.py` 之后打开 `http://<IP>:8000/app/index.html`，手机浏览器直接用。

三个主页面，另加编辑、详情、扫码三个次级页：

| 页面 | 做什么 |
|---|---|
| **名片夹** | 收到的所有名片 · 按类型筛选（类型可自定义） · **列表 / 地图双模式** · 搜索姓名/店名/类型/街道 |
| **我的名片** | 一个人可以有多张（店铺一张、跑腿一张） · 点进去编辑、分享、歇业 |
| **设置** | 自动同步开关 · 名片类型增删 · 设备指纹 · 备份/恢复 |

名片字段：**姓名、单位/店名、类型、地址、电话、提供什么、营业时间、地图位置、版本号**。
「姓名」和「单位/店名」**填一个就成立**，两个都空才算空码 ——
所以没有店铺的个人也能有一张名片（跑腿、手艺人、临时帮工）。

**类型**决定名片夹顶部的筛选条，默认给了六个（餐饮、日用百货、维修、理发、跑腿、其他），
在设置里可以随时增删；删掉一个类型不会动到已经用它建好的名片。

**没有担保流程**——谁录入的就算谁的，界面上一眼能看出「我发布的」还是「邻居捎来」。

其他特性：

- **收藏**：点卡片右上角星标，按「收藏」筛选只看常去的店（存在本机）
- **歇业开关**：我的发布里一键歇业/开业，营业状态不会自己过期
- **分享二维码**：把某张名片生成二维码，邻居点右上角**扫一扫**，对准就自动收进手机
  - **实时取景**：摄像头画面逐帧丢给 jsQR，对准就识别，不用先拍照；拿不到摄像头才退回「拍一张再认」
  - 二维码里**只有店铺数据，不含任何服务器地址**——换台电脑、换个网络，码照样有效
  - 二维码在客户端本地生成（`app/qrcode.js`），解码在本地（`app/jsQR.js`），全程不走网络
  - 收下来的名片带「邻居捎来」标记：**进不了「我的发布」，也没有歇业/删除按钮**。
    只有原发布者本人才动得了它；捎来的这份想清掉，用详情页底部「从我这台手机上移除」
- **真地图 + 离线**：瓦片由服务端代理（`/tiles/{z}/{x}/{y}.png`）并落盘到 `data/tiles/`，
  手机端同源加载，无跨域；服务端攒下多少，断网就能看多少
- **自动同步（默认关闭）**：开启后，同一个 WiFi 下的手机自动对账补差
  - 装成 APK 时，每台手机自己就是节点（`LocalNode.java`：HTTP 47475 + UDP 47474 发现），
    JS 完全不碰网络
  - 网页版走 `POST /api/p2p/exchange`，同一套协议
  - **只交换双方都持有的名片**：请求方带上自己有的名片 id，对方只收交集内的事件、
    也只回交集内的，陌生名片永远进不来
  - 要求两台手机连同一个路由器且都开着名片，所以默认不开 —— 一直开着只会白耗电

> 首次打开某片区域要等地图加载（每张瓦片约 1 秒），加载过的会落盘，之后秒开。
> URL 支持 `?page=xxx&mode=map&q=关键词&add=<分享码>&demo=1` 直接打开某个状态。
> `demo=1` 会塞四张示例名片，方便看效果。

## 同步能走多远（现实清单）

两台手机之间，数据只能通过这几条物理通道过去：

| 通道 | 前提 | 要谁开 App | 评价 |
|---|---|---|---|
| 二维码 | 一方屏幕、一方摄像头 | **只要一方** | 唯一不需要双方配合的通道，永远可用 |
| 同一个 WiFi | 连同一个路由器 | 双方都要 | 也就是「自动同步」那一档 |
| 蓝牙 / WiFi Direct | 硬件支持 | 双方都要 | 安卓后台限流厉害，暂不做 |
| 转发二维码图片 | 走微信等已有通道 | 只要收图的人扫 | 零基础设施的「广播」，最实用 |

> 没有共享网络，就没有物理通道 —— 这是物理限制，不是技术选型。所以跨网络刷新
> 只能靠「见面再扫」或「有人把新码转给你」，而不是靠后台静默同步。
